## 版本编号规则

### 1. 当前版本 100

- `100` 是当前稳定版，也是后续所有开发的基准。
- 不直接在 `100` 上开发或叠加测试改动。
- `stable/100` 作为稳定基准分支保留。

### 2. 测试开发版本

从当前稳定版派生测试分支，按顺序编号：

- `100B1`
- `100B2`
- `100B3`
- 后续依次递增。

建议 Git 分支命名为 `test/100B1`、`test/100B2`、`test/100B3`。

测试分支用于尝试新功能、修复问题和验证，不自动成为稳定版。

### 3. 升级为新稳定版

- 测试版本经过实际使用验证，并由用户明确确认后，才升级为新的稳定版。
- 例如：确认 `100B3` 合格后，将其确定为 `101`，建立 `stable/101`。
- 下一轮开发再从 `101` 派生 `101B1`、`101B2`、`101B3`。
- 后续依次为 `102`、`103`……

## 版本保护规则

1. 稳定版、测试版、还原点版是三个不同概念，必须分别记录。
2. 当前稳定版为 `100`；测试版按 B1、B2、B3 递增。
3. 只有用户明确确认测试版本升级，才能建立新的稳定版编号。
4. 测试失败或出现严重问题时，回到当前稳定版基准，不在故障版本上持续堆补丁。
5. **还原点版独立管理**：本次只将 990B5 定为稳定版/基准版 100，不代表更新还原点；还原点保持原指定状态，除非用户另行明确指定。
6. 历史分支（包括 990、990B1～990B5）保留，不因新编号而删除或覆盖。
